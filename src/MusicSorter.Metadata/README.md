# Metadata and index

- The ordinary scan reads local tags only. [TagLibSharp 2.3.0](https://www.nuget.org/packages/TagLibSharp/2.3.0) returns the first nonblank performer/genre, any title and a year if present. Unsupported or corrupt media are handled by the caller. Only call `FillMissing` for a staged export copy; a changed copy no longer has the source file's SHA-256. Existing nonblank fields are never intentionally replaced. Uncommon tag layouts and other embedded metadata are subject to the library's format support.
- A versioned per-source JSON cache lives in platform local application data (`MusicSorter/Index`). Set `MUSIC_SORTER_INDEX_DIR` to an absolute directory to isolate synthetic tests. It contains absolute source paths, metadata, SHA-256 and optional local fingerprints, not audio or API keys. It is not an SQLite database, not encrypted, and is not a substitute for inspecting the current files. Snapshots use atomic replacement, last writer wins. Deleting the local cache files removes the retained snapshots.
- [Chromaprint](https://github.com/acoustid/chromaprint) is optional and explicitly invoked. Set `MUSIC_SORTER_FPCALC` to a trusted executable path or provide `fpcalc` via the application folder or PATH. The adapter runs the tool directly without a shell and computes compressed and raw fingerprints locally from the first 120 seconds. The similarity score only suggests variants for review; it is not an identity or duplicate decision. Only byte-for-byte SHA-256 matches qualify for deduplication.
- [MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API) sends only explicitly approved artist/title text and optional duration, never a path, file or fingerprint. [AcoustID](https://acoustid.org/webservice) is a separate opt-in fallback that sends a compressed fingerprint, duration and the application key from `ACOUSTID_API_KEY`, never the path, file contents or uncompressed words. Neither client auto-applies metadata or participates in an ordinary scan. Review service terms for commercial use; free web-service access is for noncommercial use. A valid AcoustID application key is not a user API key.
- Remote adapters do not follow redirects and do not retry automatically. Errors and timeouts remain visible to the caller instead of being represented as “no matches.”


## Saved profiles and open-window indexing

- Each saved profile has its own atomically replaced local file under `MusicSorter/Profiles`. Use an absolute `MUSIC_SORTER_PROFILE_DIR` for isolated tests. Profiles remember folders and the filename pattern, not audio or lookup credentials. Profile validation accepts an offline folder as a saved path without opening it.
- A running profile session publishes the cached view, scans currently available source roots, then watches those folders recursively. File events are coalesced for 350 ms; if no event arrives, a refresh runs after 45 seconds. A missing/unreadable root leaves earlier rows visible with a warning. No daemon persists after the session is disposed; a regular rescan still re-reads tags and hashes to observe local changes, but a byte-identical cache is not rewritten.
- If a supported `fpcalc` installation is available, optional local fingerprints are indexed by original SHA-256 with no more than two computations at once. Published tags/hashes do not wait for a large fingerprint first pass. Files are rechecked against the original SHA-256 before and after optional fingerprinting, and no lookup service is called automatically.
